# 仓库结构规范

## 顶层边界

本仓库允许同时保存行情追踪工程和可复用 Codex/扣子 skill，但必须按目录隔离：

- `config/`：行情追踪配置
- `scripts/`：行情追踪运行脚本
- `data/`：行情追踪运行数据
- `reports/`：行情追踪报告
- `issues/`：行情追踪问题日志
- `docs/`：仓库和行情追踪文档
- `skills/<skill-name>/`：独立 skill 包

禁止把 skill 的 `SKILL.md` 放在仓库根目录；禁止把 skill 脚本放进行情工程的 `scripts/`。

## Skill 目录标准

每个 skill 使用独立目录：

```text
skills/<skill-name>/
├── SKILL.md
├── scripts/
│   └── ...
└── data/
    └── ...  # 本地运行态数据，默认不提交
```

`anti-pretend-effort` 的标准路径：

```text
skills/anti-pretend-effort/SKILL.md
skills/anti-pretend-effort/scripts/goal_card_manager.py
```

## 扣子提交规则

1. 提交前先在仓库根目录执行 `git status --short`。
2. 如果只改 skill，只允许出现 `skills/<skill-name>/...` 和必要文档变更。
3. 如果只改行情追踪，不要改 `skills/`。
4. 不要在子目录里单独 `git init`。
5. 不要把另一个仓库 `pull` 到当前仓库子目录后直接合并提交。
6. 每次提交信息写清楚范围，例如：
   - `skill: add anti-pretend-effort goal card manager`
   - `fix: v2.15.0 repair daily report fallback`

## 推荐拆仓方案

当前可先采用 mono-repo 隔离目录方案。后续如果 skill 数量变多，再拆成两个远程仓库：

- `zhuanzhuan-AI`：行情追踪工程
- `codex-skills`：所有可复用 skill

拆仓前不要混用两个远程来源。
