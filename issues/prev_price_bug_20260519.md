# prev_price Bug：虚假S级异动

## 问题描述
异动检测基于 `change_1d`（日环比）判断异动等级，但 `prev_price` 字段存在以下问题导致频繁出现虚假S级信号：

## 已知案例

### 1. DDR5 32G
- 2026-05-16: prev_price=925（异常低），current=1799 → 日环比+94.5%（假S级）
- 2026-05-17: prev_price=1799（异常高），current=1143 → 日环比-36.5%（假S级）
- 根因：prev_price来源不稳定，有时是爱回收价，有时是闲鱼市场价

### 2. i5 13600K
- 2026-05-16: prev_price=1269，采价脏数据写入651 → 日环比-48.7%（假S级）
- 根因：采价失败时写入异常值，未做合理性校验

### 3. 小米手环10
- 2026-05-16: prev_price=208（闲鱼市场价），写入38（闲鱼官方回收价）→ 日环比-69.6%（假S级）
- 根因：跨平台比价，不同平台价格量级不同

### 4. DDR4 16G
- 2026-05-19: prev_price=320（旧脏数据），current=398 → 日环比+24.4%（假S级）
- 根因：历史脏数据未清理，影响后续日环比计算

## 根因分析
1. **prev_price来源不统一**：同产品不同平台价格混用，导致环比失真
2. **采价异常值无校验**：写入时只校验范围（非行情价跳过），不校验日环比合理性
3. **脏数据无清理机制**：异常写入后prev_price被污染，影响后续所有日环比计算
4. **跨平台比价**：闲鱼市场价 vs 爱回收 vs 闲鱼官方回收，价格量级不同

## 建议修复方案
1. `update_xianyu_market.py` 写入时增加日环比合理性校验：|change|>30% 标记待确认
2. `price_data_validator.py` 增加 prev_price 一致性检查：同一产品的prev_price必须来自同一平台
3. 新增 `scripts/clean_dirty_prices.py`：手动/自动清理已知的脏数据点
4. 异动检测时区分数据源，同平台内环比，不跨平台

## 优先级
P1 — 每天都出假S级，严重影响异动检测可信度
