# 仓库结构规范

## 顶层边界

本仓库仅保存行情追踪工程。反卷教练已迁移到独立仓库：

- `zhuanzhuan-AI`：行情追踪、日报、异动、新品、微博信号，可使用企微 webhook
- `zhuanzhuan-anti-coach`：反卷教练、目标卡、6个扣子日程模板，只允许 `coze` 渠道

- `config/`：行情追踪配置
- `scripts/`：行情追踪运行脚本
- `data/`：行情追踪运行数据
- `reports/`：行情追踪报告
- `issues/`：行情追踪问题日志
- `docs/`：仓库和行情追踪文档

禁止把反卷教练的 `SKILL.md`、模板、目标卡脚本或日程配置放回本仓库。任何 coaching 内容都不得复用行情企微 webhook。

## 独立仓边界

反卷教练标准路径在独立仓：

```text
zhuanzhuan-anti-coach/
├── SKILL.md
├── config/
├── policy/
├── templates/coze_schedules/
├── scripts/
│   ├── goal_card_manager.py
│   └── validate_channels.py
└── data/
    └── ...  # 本地运行态数据，默认不提交
```

## 扣子提交规则

1. 提交前先在仓库根目录执行 `git status --short`。
2. 行情任务只在 `zhuanzhuan-AI` 执行，不要改 `zhuanzhuan-anti-coach`。
3. 反卷教练任务必须先切换到 `zhuanzhuan-anti-coach`，不要改行情仓。
4. 不要把另一个仓库 `pull` 到当前仓库子目录后直接合并提交。
5. 每次提交信息写清楚范围，例如：
   - `fix: v2.15.0 repair daily report fallback`
   - `docs: update coze handoff notes`

## 当前拆仓方案

当前已采用两个远程仓库隔离：

- `zhuanzhuan-AI`：行情追踪工程
- `zhuanzhuan-anti-coach`：反卷教练独立工程

扣子虽然是单 agent/单工作目录模型，但执行不同任务前必须进入对应仓库目录，避免把 coaching 消息、企微 webhook、行情脚本混在同一轮任务里。
