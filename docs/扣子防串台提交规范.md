# 扣子防串台提交规范

目标：防止日志、运行数据、反卷教练代码、行情代码在同一次提交里混在一起。

## 一、提交前必跑

在行情仓提交前执行：

```bash
python3 scripts/validate_commit_boundary.py
```

该脚本默认检查 staged files。失败时不要提交，先拆分或取消暂存。

## 二、行情仓允许什么

行情仓 `zhuanzhuan-AI` 只允许维护：

- 行情代码：`scripts/`
- 行情配置：`config/`
- 行情文档：`docs/`、`issues/`
- 必要行情缓存：例如 `data/price_cache.json`
- 脱敏排障包：`debug_snapshots/`

## 三、行情仓禁止什么

禁止提交：

- 原始日志：`logs/`、`data/logs/`
- 生成卡片/导出文件：`data/report_cards/`、`data/outbox/`、`data/periodic_reports/`
- 反卷教练目录：`skills/anti-involution-coach/`、`skills/anti-pretend-effort/`
- 反卷教练独立仓内容：`zhuanzhuan-anti-coach/`
- 代码/配置变更和运行态 `data/` 文件混在同一个 commit

## 四、需要提交日志怎么办

不要提交原始日志。先生成脱敏排障快照：

```bash
python3 scripts/collect_debug_snapshot.py --name latest
git add debug_snapshots/latest
python3 scripts/validate_commit_boundary.py
git commit -m "debug: add sanitized runtime snapshot"
```

## 五、推荐提交拆分

- 代码修复：只提交 `scripts/`、`config/`、`docs/`、`issues/`
- 运行数据：如确有必要，只单独提交允许的数据文件
- 排障材料：只提交 `debug_snapshots/`

每次 push 前确认：

```bash
git status --short
python3 scripts/validate_commit_boundary.py
git push origin local/dev
```
