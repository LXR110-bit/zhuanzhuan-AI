# Coze 3.0 多 Agent 总控路由说明

> 适用范围：AI行情监控 + 反卷教练V2.0 的 Coze 3.0 多 Agent 拆分。
> 核心原则：总控 Agent 只做识别和分流，不直接执行任何业务脚本。

## 一、Agent 拓扑

| Agent | 工作目录 | 主要职责 | 输出渠道 |
| --- | --- | --- | --- |
| 总控 Agent | 不固定业务仓 | 判断用户意图、选择专职 Agent、拆分复合请求 | 扣子主对话 |
| 价格监控 Agent | `/root/coze-production/zhuanzhuan-AI` | 采价、价格校验、日报价格产物、价格推送 | 扣子主对话 + 飞书 |
| 信号监控 Agent | `/root/coze-production/zhuanzhuan-AI` | 热点资讯、政策/新品/平台信号、S/A/B 分级和信号推送 | 扣子主对话 + 飞书 |
| 反卷教练 Agent | `/Users/lilixiaoran/工作/转转/zhuanzhuan-anti-coach` | 周规划、日校准、中段感知、下班复盘、业务观察沉淀 | 扣子主对话 |

## 二、总控 Agent 硬规则

1. 不直接运行 `python3 scripts/...`。
2. 不读取、复制、转发任何业务仓的密钥、机器人地址或本地运行数据。
3. 不在一个子任务里跨仓执行；复合需求必须拆成两个子任务。
4. 不确定用户意图时，只问一句澄清，不能自行猜测后跨仓运行。
5. 分流前先判断是否存在渠道风险：coaching 内容永远不能流向企业微信，行情推送配置永远不能进入反卷仓。

## 三、路由规则

| 用户意图关键词/场景 | 路由目标 | 处理方式 |
| --- | --- | --- |
| 价格、日报、采价、回收价、价格异常、闲鱼、爱回收、转转回收、价格卡片 | 价格监控 Agent | 进入行情仓，只执行价格链路脚本和价格日程 |
| 热点、资讯、新品、政策、平台变化、TikHub、S/A/B 信号、信号推送 | 信号监控 Agent | 进入行情仓，只执行信号采集、去重、分级和信号推送 |
| 反卷、复盘、周计划、日校准、目标卡、业务观察、思维差异、成长、清醒伙伴 | 反卷教练 Agent | 进入反卷仓，按 `templates/coze_schedules/` 和 `扣子接入说明.md` 执行 |
| 同时包含行情和工作规划 | 总控 Agent 拆分 | 先分解为行情子任务和反卷子任务，分别交给专职 Agent |
| 意图不明确，例如“帮我看看今天怎么样” | 总控 Agent 澄清 | 询问“你是想看行情日报，还是做今天工作复盘？” |

## 四、典型验收示例

- “今天行情日报怎么样？” → 价格监控 Agent。
- “今天有什么新品/政策/热点信号？” → 信号监控 Agent。
- “帮我做今天复盘” → 反卷教练 Agent。
- “帮我看看明天工作和行情都怎么安排” → 总控 Agent 拆成两个子任务：行情监控看市场/推送，反卷教练做工作安排。
- “10 点没推送，顺便帮我复盘今天工作” → 先交行情监控 Agent 排查 10 点推送，再交反卷教练 Agent 做复盘；两个子任务不能共享环境变量或运行目录。

## 五、防串台检查

- 行情仓提交前运行：`python3 scripts/validate_commit_boundary.py`。
- 反卷仓提交前运行：`python3 scripts/validate_channels.py` 和 `python3 scripts/validate_commit_boundary.py`。
- 总控 Agent 发现跨仓、跨渠道、复合请求时，必须拆分，不允许把一个仓的配置复制给另一个仓。

## 六、生产手册

Coze 正式启用和日常运行时，直接按 `docs/Coze3_生产手册.md` 执行。该手册定义总控 Agent、行情监控 Agent、反卷教练 Agent 的生产职责、固定工作目录、校验命令和复合请求拆分方式。
