## 一、任务卡死防护方案（已集成）

### 问题背景
2026-04-26 晚间异动检测：小米手环10任务丢失，整个流程卡死，日报未生成。

### 根因分析
截止机制和爬虫共享同一进程，任务丢失后截止机制无法触发。

### 解决方案：独立看门狗进程

**文件位置**：`scripts/watchdog.py`

**核心功能**：
```python
CONFIG = {
    "check_interval": 30,        # 30秒检查一次
    "stale_threshold": 600,      # 数据超过10分钟未更新视为异常
    "max_restart_attempts": 3,   # 最大重启次数
    "deadline": "23:00",         # 强制截止时间
    "alert_webhook": "企业微信机器人URL"
}
```

**启动方式（每晚21:00检测前执行）**：
```bash
cd ./运动相机追踪 && python3 scripts/watchdog.py &
```
- watchdog与爬虫进程分离，互不影响
- **必须在爬虫启动前启动watchdog**
- 检测结束后执行：`pkill -f watchdog.py`

**监控逻辑**：
1. 每30秒检查 `progress.json` 最后更新时间
2. 超过10分钟未更新 → 尝试重启爬虫
3. 重启失败超过3次 → 发送告警到企业微信
4. 到达23:00 → 强制结束，生成不完整日报

## 二、三价格爬取方案（已集成）

### 问题背景
原有三价格爬取逻辑内联在skill中，skill内容过多时被丢弃，导致功能丢失。

### Opus分析结论
爱回收/闲鱼官方回收对PC硬件（显卡/CPU/内存）覆盖率低（27%/67%），大部分机型"暂无报价"是**正常结果**，不是技术问题。

### 解决方案：Calendar/sub-agent执行 + Python后处理 + null处理策略

**执行入口**：Calendar 日程描述 -> sub-agent -> `search_web`/`mobile_use`

**日程与工具模板**：
- `扣子原价格爬取功能/日程描述模板_20260429.md`
- `扣子原价格爬取功能/工具调用模板_20260429.md`

**Python后处理**：
- `scripts/price_data_validator.py`
- `scripts/price_daily_recorder.py`
- `scripts/price_archiver.py archive`
- `scripts/generate_daily_report_payload.py`
- `scripts/render_report_cards.py`

**三价格源覆盖率**：
| 数据源 | 获取方式 | 覆盖率 | 适用品类 |
|--------|----------|--------|----------|
| 闲鱼市场价 | search_web | 100% | 全品类 |
| 闲鱼官方回收价 | 云手机 | 67% | 手机/数码/手环 |
| 爱回收价 | 云手机/search_web | 27% | 手机/平板/手环 |

**价格null处理策略（重要！）**：
1. **有几个价格就记录几个，不要推测填充**
2. **null显示为"—"，并标注原因**
3. **日报按品类分区展示**：
   ```

   DJI Pocket 3  市场1568 | 闲鱼官方1344 | 爱回收1770
   
   【PC硬件】市场价参考（该品类暂无官方回收渠道）
   RTX 3060  市场1405
   RTX 4070  市场2950 | 闲鱼官方2036
   ```

**数据存储格式**：
```json
{
  "product_id": "rtx4070",
  "product_name": "微星 RTX 4070",
  "crawl_time": "2026-04-27T09:00:00",
  "prices": {
    "闲鱼市场价": {"price": 2914, "source": "search_web", "data_count": 14},
    "闲鱼回收价": {"price": null, "source": "平台不收", "note": "PC硬件不在闲鱼官方回收范围"},
    "爱回收价": {"price": null, "source": "平台不收", "note": "PC硬件不在爱回收范围"}
  },
  "change": {
    "type": "日环比",
    "value": "-1.2%",
    "baseline": 2950
  }
}
```

**展示规范**：
- 必须标注数据源名称（闲鱼市场价/闲鱼回收价/爱回收价）
- 必须标注环比类型（日环比/周环比）
- 价格变动必须明确对比基准
- **null必须显示"—"并标注原因，禁止推测填充**

## 三、信号时效性规则（已集成）

### 问题背景
Pocket 4 发布11天后仍作为S级信号推送，信息时效性判断缺失。

### 解决方案：自动降级机制

**文件位置**：`scripts/signal_freshness.py`

**降级规则**：
```python
def evaluate_signal_level(event_date_str: str, base_level: str = "S") -> str:
    """
    发布 <= 3天：保持原级别 (S → S)
    发布 4-7天：降一级 (S → A)
    发布 > 7天：降两级 (S → B)
    """
    days_elapsed = (now - event_date).days
    
    if days_elapsed <= 3:
        downgrade = 0
    elif days_elapsed <= 7:
        downgrade = 1
    else:
        downgrade = 2
```

**应用场景**：
- 新品发布信号
- 官方降价信号
- 政策调整信号

**集成方式（05:30信号分级/06:00图片生成前执行）**：
```python
from scripts.signal_freshness import evaluate_signal_level

# 对每个信号评估时效性
for signal in signals:
    event_date = signal['publish_date']
    base_level = signal['level']
    actual_level = evaluate_signal_level(event_date, base_level)
    signal['final_level'] = actual_level
```

**示例**：
- Pocket 4 发布于 2026-04-16
- 今日 2026-04-27，已过11天
- 原级别S → 实际级别B（降两级）

**报告标注格式**：
```
[信号名称] | [原始级别] → [降级后级别] | 发布于XX天前
```

## 七、故障排查清单

### 任务卡死
1. 检查 `data/progress.json` 最后更新时间
2. 检查 `crawler.pid` 进程是否存活
3. 查看 `logs/watchdog.log` 日志
4. 手动启动 watchdog：`python scripts/watchdog.py`

### 三价格丢失
1. 检查云手机配额（每日2次上限）
2. 检查 `data/price_cache.json` 是否包含三价格字段
3. 验证 Calendar 日程描述是否使用 sub-agent 模板
4. 验证 sub-agent 是否已把 `search_web`/`mobile_use` 结果写入 `data/price_cache.json`
5. 再运行验证、归档、日报生成等 Python 后处理脚本

### 信号时效性异常
1. 检查 `signal_freshness.py` 是否集成
2. 验证事件日期格式是否正确（YYYY-MM-DD）

### 5.5 可信度评估模型（已修复）

**原问题**："信号一致性"维度会惩罚异动信号，但真正有价值的异动恰恰是偏离趋势的

**修复后模型**：

| 维度 | 分值 | 说明 |
|------|------|------|
| 源权威性 | 0-25 | 官方渠道25，头部KOL 20，普通博主12，匿名5 |
| 时效性 | 0-25 | <6h 25，6-24h 20，1-3天10，>3天5 |
| 交叉验证 | 0-25 | ≥3个独立源25，2个源18，仅单源8 |
| 信号一致性 | 0-25 | **已修复**，见下表 |

**信号一致性评分规则（修复后）**：
| 条件 | 分值 | 说明 |
|------|------|------|
| 与7天趋势一致 | 20 | 正常波动 |
| 偏离<10% + 有明确原因 | 25 | 有原因的异动加分 |
| 偏离<10% + 无明确原因 | 15 | 需观察 |
| 偏离>10% + 有明确原因 | 20 | 重大异动，有原因支撑 |
| 偏离>10% + 无明确原因 | 5 | 疑似噪声 |

**明确原因关键词**：
- 官方降价、新品发布、停产公告、政策调整、供应链事件

**采纳规则**：
- ≥75分：自动采纳
- 50-74分：人工确认后采纳
- <50分：仅记录，不参与决策

## 九、品牌切换后处理规则

### 问题背景
2026-04-27 将监控品类基准品牌从"RTX 4070"改为"微星 RTX 4070"，从"DDR5 16G"改为"金士顿 DDR5 16G"。

新旧品牌价格差异20-30%，直接比较会产生虚假异动。

### 处理规则

**品牌切换当天必须执行**：
```bash
cd ./运动相机追踪 && python3 scripts/price_archiver.py reset-baseline
```

**异动检测豁免**：
- 品牌切换当天，该品类的异动检测跳过
- 在progress.json中标注"品牌切换豁免"
- 次日恢复正常检测

**历史数据处理**：
- 旧品牌历史数据保留，但标注"已废弃"
- 新品牌从切换当天开始积累数据
