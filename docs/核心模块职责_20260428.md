# 核心模块职责与数据约束

**日期**：2026-04-28  
**优先级**：高。本文描述当前行情监控系统的真实业务分层；调度执行以 `config/schedule.json` 为准。

## 一、核心模块职责

| 模块 | 触发时间 | 职责 | 数据来源 | 输出 |
|---|---:|---|---|---|
| 市场追踪日报 | 06:00 | 资讯整合、信号分级、收购建议 | search_web、RSS、IT之家、TikHub | 图片卡片日报 |
| 白天异动检测 | 7:30 / 12:00 / 17:30 | A层8个机型轻量检测 | search_web | 日报 + 告警 |
| 晚间全量检测 | 21:00 | A+B层22个机型深度爬取 | mobile_use(闲鱼) | 图片卡片日报 |
| 云电脑扫描 | 每2小时 | 轻量价格扫描 + 异动检测 | search_web | 日志 + 告警 |

## 三、价格数据来源

| 数据源 | 获取方式 | 覆盖率 | 适用品类 |
|---|---|---:|---|
| 闲鱼自由市场价格 | search_web / Coze缓存 | 100% | 全品类 |
| 闲鱼官方回收价格 | mobile_use | 67% | 手机 / 数码 / 手环 |
| 爱回收价格 | mobile_use / search_web | 27% | 手机 / 平板 / 手环 |

关键约束：

- PC硬件（显卡、CPU、内存）在闲鱼官方回收和爱回收覆盖率低，`暂无报价` 是正常结果。
- `null` 必须显示为 `—` 并标注原因，禁止推测填充。

mobile_use 执行模板：

```text
在闲鱼App搜索"{search_term}"，筛选"轻微使用痕迹"，
取前5个有效商品价格，返回价格列表和中位数。超时90秒。

在闲鱼App搜索"{search_term}"，进入回收服务页面，获取官方回收价格。
筛选"轻微使用痕迹"（对应9成新），返回价格数据。超时90秒。

打开爱回收App，搜索"{search_term}"，获取基础价、券后价、碳索家价。
筛选"轻微使用痕迹"（对应9成新）。超时90秒。
```

模板文件：`config/mobile_use_templates.json`。

## 四、异动检测算法

5种算法融合，需至少3个同时判定才确认异动：

| 算法 | 权重 |
|---|---:|
| 3σ法则 | 25% |
| 趋势突变 | 25% |
| 分布漂移 | 20% |
| 孤立森林 | 15% |
| IQR异常 | 15% |

判定逻辑：

| 等级 | 条件 |
|---|---|
| S级 | ≥3算法 + 跌幅 > 30% + 置信度 > 90% |
| A级 | ≥3算法 + 置信度 70-90% |
| B级 | <3算法 + 需持续观察 |

## 五、数据流转

```text
1. search_web爬取价格 -> 写入 data/price_cache.json
2. 数据验证层 -> 写入 data/validation_report.json
3. 每日三平台价格记录 -> 写入 data/daily_price_records/{日期}.json
4. 异动检测算法 -> 写入 data/anomaly_votes.json
5. 连续确认（第2次仍异动）-> 触发推送
6. 推送前验证 -> 企业微信Webhook
7. 每日归档 -> data/trend_history/{产品ID}/{日期}.json
```

资讯信号流转：

```text
1. 原始资讯信号 -> data/news_signals.json
2. 标注发布时间 + 读取7天去重历史 -> data/news_signal_dedupe_history.json
3. 7天窗口去重后 -> data/news_signals_filtered.json
4. 超过7天、缺少发布时间、7天内重复出现 -> 不进入日报
```

价格播报约束：

- 每日记录：闲鱼自由市场价格、闲鱼官方回收价格、爱回收价格；不再使用拼多多。
- 价格监控日报只播报价格和日环比，不混入资讯长文。
- 价格卡片必须展示这三类价格口径：闲鱼自由市场价格、闲鱼官方回收价格、爱回收价格。

## 六、当前修复优先级

P0：

- 数据验证层：价格合理性校验，变动 >30% 标记人工确认。
- 扫描一致性检查：对比上次结果，变动 >20% 预警。

P1：

- S级判定逻辑：增加跌幅百分比维度。
- baseline自动更新：每周生成 `data/baseline_update_proposal.json`，人工确认后再写入 `config/baseline.json`。

P2：

- 数据源多样化：mobile_use验证。
- 告警去重：同一产品24h内只推送一次。
