## 二、预测模型建立

### 2.1 回收量变化曲线模型

基于 Pocket 4 数据，拟合新品发布后回收量变化的典型曲线：

```
Q(t) = Q_base + ΔQ × f(t)

其中：
- Q(t): 第t天的回收量
- Q_base: 日常基准量 (300台)
- ΔQ: 峰值增量 = 200台
- f(t): 时间响应函数
```

#### 响应函数 f(t) 的特征

```
f(t) = 
  0,                    t < -5 (发布前平稳期)
  α × (t+5)/5,         -5 ≤ t < 0 (发布前预热期)
  β × exp(-γ×t),       t ≥ 0 (发布后冲击-衰减期)
  
参数拟合：
- α = 0.39 (发布前5天已有+16%涨幅)
- β = 0.67 (峰值相对日常的涨幅系数)
- γ = 0.18 (衰减速率)
```

### 2.2 峰值时间预测模型

**核心发现：峰值出现在发布后第3天**

#### 影响因素分析

| 因素 | 影响分析 |
|------|---------|
| 信息传播延迟 | 电商平台上新 → 用户感知 → 决策约需 **2-3天** |
| 决策周期 | 回收需求非冲动型购买，决策周期 2-3天 |
| 竞品对比 | 用户在新机发布后观望，等待价格稳定 |
| 渠道铺货 | 线下渠道需要 2-3天 完成新品铺货 |

#### 峰值时间公式

```
T_peak = T_release + τ

其中：
- T_release: 发布日
- τ = 3天 (峰值延迟)
```

**置信区间：τ ∈ [2, 4] 天**

### 2.3 峰值涨幅预测模型

#### 影响因子

| 因子 | 权重 | 说明 |
|------|------|------|
| 产品热度 | 0.4 | 搜索指数、社交讨论量 |
| 定价策略 | 0.3 | 新品定价 vs 旧品差价 |
| 渠道密度 | 0.2 | 线上线下铺货速度 |
| 市场存量 | 0.1 | 旧款持有量 |

#### 涨幅估算公式

```
ΔV_peak = K × H × P

其中：
- K: 品类系数 (运动相机=1.0, 显卡=1.5, CPU=0.8)
- H: 热度指数 (0.5-2.0, 基于搜索量归一化)
- P: 价格敏感系数 (定价差/旧品价格)
- ΔV_peak: 峰值涨幅预估

Pocket 4 示例：
ΔV_peak ≈ 1.0 × 1.2 × 0.5 ≈ 60%
实际观测: +67% ✓
```

### 2.4 回落规律模型

#### 衰减曲线拟合

```
Q(t) = Q_peak × exp(-λ × (t - T_peak)) + Q_base × (1 - exp(-λ × (t - T_peak)))

其中：
- λ = 0.35 (衰减常数，对应半衰期约2天)
- Q_peak = 500台
- Q_base = 300台
```

#### 关键时间节点预测

| 阶段 | 天数 | 回收量 | 占峰值比例 |
|------|------|--------|-----------|
| 峰值 | 3 | 500台 | 100% |
| 快速回落 | 4-5 | 380台 | 76% |
| 初步稳定 | 6-7 | 340台 | 68% |
| 基本恢复 | 8-9 | 320台 | 64% |
| 完全恢复 | 9-10 | 300台 | 60% |

## 四、操作建议

### 4.1 新品发布准备时间线

```
发布前10天
├── 建立数据监控 (搜索指数、社交热度)
├── 评估新品热度等级 (A/B/C级)
└── 初步备货量预估

发布前5天
├── 启动回收预热 (小幅提价收购)
├── 预订仓储空间 +20%
└── 预备流动资金 +50%

发布前1天
├── 确认最终备货量
├── 人员排班调整 (发布后3天+50%人力)
└── 资金到位检查

发布日
└── 密切监控回收量变化

发布后0-3天
├── 全力收购 (峰值期)
├── 快速周转，避免积压
└── 每6小时汇报一次回收量

发布后4-9天
├── 逐步收缩收购量
├── 价格敏感度提高
└── 开始关注二级市场转售时机

发布后10天+
└── 恢复正常运营
```

### 4.2 人力配置建议

| 阶段 | 人力倍数 | 持续天数 |
|------|---------|---------|
| 发布前 | 1.0x | 5天 |
| 峰值期(发布后0-3天) | **1.5x** | 3天 |
| 回落期(发布后4-9天) | 1.2x | 6天 |
| 恢复期(发布后10天+) | 1.0x | - |

### 4.3 资金配置建议

| 阶段 | 资金倍数 | 说明 |
|------|---------|------|
| 发布前 | 1.0x | 日常运营资金 |
| 峰值期 | **1.8x** | 覆盖+80%回收增量 |
| 回落期 | 1.3x | 逐步收缩 |
| 恢复期 | 1.0x | 恢复正常 |

### 4.4 收手时机判断

**以下信号出现时，应果断减少收购：**

1. **回收量连续3天低于日常基准** → 热度消退信号
2. **新品价格跌破发行价15%** → 市场看跌信号
3. **渠道库存积压** → 供应过剩信号
4. **竞争对手开始低价抛售** → 价格战信号

## 五、异动检测优化建议

### 5.1 当前问题

- 异动检测仅关注**价格**维度
- 可能错过**量价配合**的先行信号

### 5.2 优化方案：增加回收量监控

#### 监控指标体系

```
1. 回收量绝对值
   - 触发阈值: 单日 > 450台 (日常+50%)

2. 回收量变化率
   - 触发阈值: 日环比 > +20%
   - 触发阈值: 3日均线 > 日常均值 +30%

3. 量价配合信号
   - 回收量↑ + 价格↓ → 潜在下跌预警
   - 回收量↑ + 价格↑ → 正常热度反应
   - 回收量↑ + 价格稳 → 观望期，持续监控
```

#### 预警分级

| 等级 | 条件 | 建议动作 |
|------|------|---------|
| 🟡 关注 | 回收量 > 400台 | 加强监控 |
| 🟠 警示 | 回收量 > 450台 连续2天 | 启动应急预案 |
| 🔴 警告 | 回收量 > 500台 | 全力收购，同时关注价格 |

### 5.3 日报改进建议

**建议在日报中增加以下内容：**

```markdown
## 回收量监控
- 今日回收量: XXX台 (日环比: ±X%)
- 3日均线: XXX台
- 相对日常基准: +XX%
- 趋势判断: [上升/平稳/下降]

## 异动预警
- [无/关注/警示/警告]
- 触发原因: XXXXX
- 建议动作: XXXXX
```

## 六、方法论核心公式汇总

### 6.1 预测公式

```
1. 峰值时间: T_peak = T_release + 3天 (置信区间: 2-4天)

2. 峰值量估算: Q_peak = Q_base × (1 + ΔV_peak)
   其中 ΔV_peak = K × H × P (品类系数 × 热度 × 价格敏感度)

3. 峰值涨幅估算: ΔV_peak ≈ 品类系数 × 热度系数 × 0.5
   - 运动相机: ~0.6 (对应+60%)
   - 显卡: ~1.0 (对应+100%)
   - CPU: ~0.5 (对应+50%)

4. 恢复周期: T_recover = 9天 (置信区间: 7-14天，取决于品类)

5. 回收量随时间变化:
   Q(t) = 300 + 200 × exp(-0.35 × max(0, t-3))  (t ≥ 0)
```

### 6.2 决策检查清单

```
□ 发布前5天启动预热
□ 发布前确认资金到位 +80%
□ 发布前确认人力 +50%
□ 发布后第3天达到峰值，全力收购
□ 发布后第4-6天逐步收缩
□ 发布后第9天恢复正常
□ 回收量连续3天低于日常基准时收手
□ 价格跌破发行价15%时停止收购
```
